叶小楠2026-11-062026-11-06

ZERO_团队入门须知

版本：v1.0

欢迎加入我们的团队。

我们希望这里不是一个“把代码写出来就完事”的地方，而是一个真正能够让大家一起做项目、解决问题、积累经验的团队。

你不需要一进来就什么都会。

但是，你必须具备学习能力、沟通能力，以及把事情做完的责任心。

如果你只是想“混一混”“等别人教”“代码报错就直接甩给别人”，那这里可能并不适合你。

一、我们的核心成员

目前团队核心成员如下：

1. Waiting

主要负责：

  • 系统运维
  • Linux / Windows 环境维护
  • 前后端代码实现
  • 项目需求对接
  • 需求整理与任务拆分
  • Git / GitHub 团队协作
  • 项目整体技术协调

简单来说：

哪里需要搭环境、哪里需要排查服务器、哪里需要协调需求、哪里需要把几个模块串起来，通常都可以找我。

2. Xiang

主要负责：

  • 核心开发
  • Python 功能实现
  • 数据处理
  • 数据可视化
  • ECharts 等可视化功能开发

简单来说：

涉及 Python、数据处理、图表展示这一块，是主要负责方向。

3. Hi-Tao

主要负责：

  • 核心开发
  • Python 功能实现
  • 后端代码开发
  • 接口功能实现
  • 后端业务逻辑

简单来说：

主要负责“后端到底怎么跑起来、数据怎么处理、接口怎么给前端提供数据”。

二、加入团队之前，你需要知道一件事

我们不要求你：

“第一天就能独立完成一个完整项目。”

这是不现实的。

但是我们要求你具备：

遇到不会的东西，自己先查；查完还不会，再带着问题来问。

例如：

❌ 不推荐：

“哥 / 兄弟 / 同学，这个怎么写？这个需求我要怎么做？”

然后什么都没有。

✅ 推荐：

“我现在需要实现一个文件上传接口，我尝试用 Flask 的 request.files 获取文件，但是运行的时候出现 KeyError: 'file'。我检查了前端请求，发现 FormData 里面的字段名可能是 upload，是不是这里不一致？”

后者就属于有效沟通。

因为你已经：

  1. 理解了任务
  2. 自己尝试过
  3. 看过报错
  4. 定位过问题
  5. 提出了自己的猜测

我们愿意教认真学习的人，但不会替一个完全不动脑子的人思考。

三、基础能力要求

1. 沟通能力

这是团队协作最重要的能力之一。

你至少需要做到：

  • 能看懂别人描述的需求
  • 能把自己的问题说清楚
  • 能准确反馈自己的开发进度
  • 遇到问题及时沟通
  • 不懂就问，但不要张口就问
  • 不确定需求时主动确认

举个最简单的例子

假设需求是：

“用户登录以后，首页显示他的用户名。”

不要理解成：

“我要搞一个登录页面。”

你应该进一步思考：

  • 用户名从哪里来？
  • 登录接口返回什么？
  • 是否需要 Token？
  • 前端怎么保存登录状态？
  • 首页怎么获取当前用户？
  • 用户退出登录以后怎么办？

这就是所谓的：

理解需求，而不是只理解一句话。

2. 基础计算机理论

你不需要现在就成为计算机专家。

但是一些最基本的概念必须知道。

至少需要了解：

  • Windows 和 Linux 的区别
  • 文件系统基本概念
  • IP 地址
  • 端口
  • HTTP / HTTPS
  • TCP / UDP 的基本概念
  • 客户端与服务器
  • 前端与后端
  • API / 接口
  • 数据库基本概念
  • Git 基础操作

例如：什么叫端口？

如果别人跟你说：

8080 是一个端口，不是 IP 地址。

十、不要直接乱改别人的代码

这是团队协作中的基本规则。

例如：

B 不应该：

“我直接改了提交一下。”

然后 A 第二天发现：

“我昨天写的东西怎么没了？”

正确方式应该是：

  1. 先确认问题
  2. 和负责的人沟通
  3. 确认修改方案
  4. 再进行修改

十二、我们不怕你不会

新人不会东西非常正常。

真正让团队头疼的是：

不会 + 不学 + 不问 + 等别人帮你做。

例如：

可以接受

“Docker 我没用过，但是我已经看了项目里的 Dockerfile，正在研究怎么启动，目前卡在容器端口映射这里。”

👍 这种新人可以培养。

不能接受

“Docker 是什么？”

然后等别人从头讲两个小时。

如果一个东西是网上搜索几分钟就能知道的基础概念：

先自己查。

十六、关于“我不会”的正确态度

你可以说：

“我不会。”

但最好紧接着说：

“我准备先学一下。”

或者：

“我查了一下，但是这里还是没搞懂。”

这说明你在主动解决问题。

不会不可怕，拒绝学习才可怕。

十七、我们希望培养什么样的人？

我们不希望培养：

只会执行命令的人。

我们希望培养的是：

拿到一个需求，能够自己分析、自己拆解、自己查资料、自己实现，遇到真正解决不了的问题再寻求帮助的人。

例如给你一个需求：

“做一个用户数据统计页面。”

我们希望你能够逐渐形成这样的思维：

这才是真正的开发能力。

十八、最后的话

加入团队不是加入一个“作业互助群”。

我们希望大家是真的能够一起：

做项目、学技术、解决问题、拿成果。

你可以不会。

你可以犯错。

你甚至可以把代码写得很烂。

但是你必须愿意改、愿意学、愿意承担自己的任务。

如果你愿意认真投入，那么团队愿意给你时间成长。

如果你只是想：

“别人写，我跟着。”

那么建议你现在就退出。

因为我们最终比拼的不是：

谁现在会得最多。

而是：

谁能够持续学习，谁能够真正把事情做完。

新成员最低能力检查表

加入团队前，建议至少做到：

  • 能正常使用 Windows
  • 知道 Linux 是什么
  • 能使用 CMD / PowerShell
  • 能进行基本 Linux 命令操作
  • 知道 IP 和端口的基本概念
  • 理解前端、后端、数据库之间的关系
  • 掌握一门编程语言基础
  • 能看懂基础 Python 代码
  • 能独立写简单 Python 程序
  • 知道 Git 是什么
  • 能完成 clone / pull / add / commit / push
  • 能看懂基本报错信息
  • 知道如何使用搜索引擎解决技术问题
  • 能清楚描述自己遇到的问题
  • 能按照要求完成自己的任务

不要求你全部精通，但至少应该具备继续学习这些内容的能力。

核心原则

先自己想，自己查，自己试。

实在解决不了，再来问。

提问不是能力差，毫无思考地提问才是。
